Blueprint · Frontend

Ruang cerita yang hangat, jelas, dan tidak menghakimi.

Panduan visual untuk semua pekerjaan FE: font, warna, bentuk, tombol, form, layout, dan copywriting yang sudah diterapkan di marketing, Login/Register, Dashboard, Brave Choice, dan Diary.

01

Enam prinsip

Dipakai sebagai tolok ukur setiap keputusan desain dan review PR.

1

Hangat & suportif

Pengguna utama adalah remaja. UI tidak boleh terasa seperti ujian, penilaian, atau peringatan keras.

2

Tanpa merah

Error memakai clay, peringatan memakai cream. Status dibedakan lewat ikon + teks + border, bukan warna saja.

3

Fungsi dulu

Redesign tidak mengubah logika, API, payload, aturan paket, atau alur autentikasi.

4

Kosong ≠ netral

Hari tanpa mood = “Belum dicatat”, bukan skor 3 atau 0. Tidak ada data demo di UI.

5

Gaya terisolasi

Setiap halaman punya scope CSS sendiri agar halaman lain tidak ikut berubah.

6

Dapat diakses

Target sentuh ≥ 44px, teks ≥ 12px, fokus terlihat, prefers-reduced-motion dihormati.

Dua lapisan sistem

Token PB20 --tt-*

Untuk komponen shadcn (Button, Input, Select, Alert) dan halaman yang belum di-redesign. Dipakai lewat utility Tailwind atau var(--tt-…).

Tema Landing/Redesign

Untuk marketing, auth, legal, dashboard, diary, dan Brave Choice. Variabel lokal di dalam scope halaman. Jangan ubah token global untuk satu halaman.

08

Copywriting

Bahasa Indonesia, sapaan “kamu”, nada hangat dan sederhana. Jangan menggurui, menilai karakter, atau menjanjikan hasil pasti.

Istilah baku
PakaiTemanCerita (satu kata) · Brave Choice · Refleksi Awal + “Baseline Assessment” · Riwayat Diary · Streak N hari
JanganBuddy · AI Companion · Brave Choice Quiz · soal · hari mencatat
Kata & elemen terlarang
Di Brave Choicebenar / salah · kurang tepat · coba pikirkan lagi · bijak (label) · % tepat · grafik akurasi · tanda silang
Gantinya“Pilihanmu” · “Ada langkah lain yang bisa kamu coba” · “Langkah ini bisa membantumu” · “3 latihan diselesaikan”
Pola feedback Brave Choice — 3 langkah
1 · Pahami“Wajar kalau kamu ingin masalahnya cepat selesai.” (per kategori; memvalidasi perasaan, tidak membenarkan tindakan berisiko)
2 · Langkah yang disarankanTeks opsi rekomendasi dari bank soal.
3 · Alasan / yang perlu diperhatikanPenjelasan dari bank soal; risiko tetap dijelaskan.
💡
Ada langkah lain yang bisa kamu coba

Wajar kalau kamu ingin masalahnya cepat selesai atau tergiur kesempatan mendapat uang.

Langkah yang disarankanMinta dasar tertulis, jangan bayar, dan konsultasi ke kampus/keluarga/layanan hukum.

Ancaman denda tanpa kontrak yang jelas perlu dicek. Bukti tertulis dan pendamping membantumu mengambil keputusan.

09

Aksesibilitas & state data

Aksesibilitas

  • Target sentuh ≥ 44×44px; teks ≥ 12px.
  • Fokus terlihat; modal menjebak fokus, Escape menutup, fokus kembali ke pemicu.
  • role="status"/aria-live untuk loading; role="alert" untuk error; aria-pressed/aria-current untuk pilihan.
  • Status tidak hanya warna: hari mendatang = garis diagonal + “Belum tiba”.
  • Animasi ≤ 0.4s; mati/lambat dengan prefers-reduced-motion.
  • Mobile: input 16px, safe-area-inset-bottom, tanpa horizontal scroll.

State data

StateAturan
LoadingPageLoader halaman; spinner kecil + teks untuk bagian
Kosonghanya bila data memang kosong; teks suportif + langkah berikutnya
Errorpesan jelas + “Coba lagi”; jangan diganti state kosong
Terkuncikotak cream + tautan nyata ke /subscription
Read-onlyikon gembok + “Hanya baca”; input diganti penjelasan

11

Checklist sebelum PR FE

  • Font ≥ 12px; hanya Jakarta / Fraunces / Caveat sesuai perannya.
  • Tidak ada merah; error memakai attention, peringatan memakai cream.
  • Warna mood diambil dari MOOD_COLORS.
  • Gaya berada di scope halaman; halaman lain tidak berubah.
  • Tombol ≥ 44px, ada fokus, tidak ada tombol tanpa aksi, submit anti-ganda.
  • Copy mengikuti istilah baku & nada suportif.
  • Loading / kosong / error / sukses semua ditangani.
  • Desktop, tablet (768px), mobile (375px) tanpa horizontal overflow.
  • Logika, API, payload tidak berubah; tes terkait diperbarui.
  • npm run lint, npx tsc --noEmit, npm test, npm run build lulus.
  • Setelah PR di-merge lalu di-revert: buat branch baru dari dev dan batalkan revert-nya, jangan buka PR dari branch lama.
Utang desain
  • Insight, Subscription, Profil, Pengaturan, Mood, Baseline, Admin belum memakai tema redesign.
  • Beberapa komponen lama masih memakai merah #DC2626 (sidebar shell, Navbar, dialog keluar, Subscription, Admin, Insight).
  • features/diary/constants/tokens.ts masih berisi alias warna lama; style inline dan isMobile dipindah ke CSS berskop saat disentuh.
  • Belum ada tes visual otomatis; verifikasi visual masih manual.
